# 拦截弹窗：检测证据与 AI 辅助决策

## 本轮已实现

- 在功能分支保留两侧提交，集成远端 3.7.0-24；主分支历史未改写。
- 弹窗分为检测证据、文件/进程、AI 建议、可展开事件身份、固定操作区。删除 AI 分析/执行建议按钮，原有自动分析与自动执行开关不变。
- 模型分数、报毒类别、平台、家族/通用分类、识别引擎、原始标签及命中规则可见。YARA 固定返回 100 只表示命中，不是概率；没有评分显示“未评分”，General 显示未确定家族。
- AI 分析中四条窗口边缘向内呈现七彩流光，透明度连续衰减；延迟启动不亮，完成/失败/取消/正在处置/空队列/断连停止，页面卸载释放轮询。遵循减少动画设置。
- 新字段有简体中文、繁体中文、英文文案；其他现有语言使用英文回退，不显示内部键名。

## 数据契约与兼容

引擎 → DetectionResult → hash_cache → 告警请求 → Web 快照 / AI 输入。

DetectionResult 是兼容既有字符串接口的结果对象：布尔判断、比较、日志、旧 JSON 标签保持兼容；附带冻结的 DetectionEvidence。这里的元数据只在内存中跟随结果对象，**JSON 字符串本身不会保留附加属性**，因此 Web 快照显式输出独立 evidence 对象。

- score 是检测器实际返回的分数，不由 AI 或规则命中数量推算。
- score_kind 区分 model_probability、cloud_score、rule_match、not_provided。
- rules 和 description 绑定到本次结果，缓存命中/跨线程读取不再依赖线程局部“上一次描述”。
- 常规进程、文件、延后扫描沿用字符串调用；DLL 路径通过 include_result=True 同时保留结果，旧 scan_process_memory 默认仍返回路径。
- 告警详情中的源路径、规则描述与 AI 理由均以 textContent 渲染，不解释 HTML。
- 新结果的精确例外身份增加实际引擎、分数类型和命中规则，以避免同名标签匹配到不同规则；旧字符串调用保持旧格式。已有精确例外可能因此重新询问，不能为兼容而扩大放行范围。
- DLL 告警仍不允许创建持久例外；文件在用户等待期间变化仍拒绝按旧身份放行。
- 云报告展示仅用于已提供的结果，本轮没有把未接通的云报告消费链路伪装成已生效检测能力。

## AI：当前加固与明确限制

本轮把同一份检测证据加入 AI 上下文，并要求文件名、路径、描述、日志只能作为不可信数据，不能当作指令；禁止编造分数、签名、家族、云报告或未观察到的行为。界面明确标示 AI 可能出错。

这些提示词约束**不能保证消除幻觉或提示注入**。当前模型输出仍是原有 allow/block + reason，未实现逐句事实校验或证据引用验证。已有自动执行若用户开启仍会按既有策略工作；本轮不新增自动允许、修改规则、执行命令或上传文件权限。

## 后续深化设计（未自动实施）

### 1. 从二选一升级为可核验建议

建议 v2 结构：verdict = allow | block | review，supporting_evidence、opposing_evidence 为本次事件证据 ID 列表，unknowns 为受限枚举，recommendation_scope 为只读建议。

后端根据允许的 schema 校验输出、证据 ID 和事件版本。不存在的证据、不受支持的动作、额外权限请求、异常数值均拒收。低温度和 JSON 格式仅减少波动，不证明事实正确。reason 尽量由通过校验的事实模板生成，模型自由解释单独标注为推断。

### 2. 误报抑制只产生窄范围草案

结合真实用户确认、文件哈希、签名验证结果、规则 ID 和触发操作归纳候选。重复次数多不代表误报，合法工具名称、目录或有效签名也不是无条件放行依据。

默认草案绑定“文件 SHA-256 + 此检测/行为 + 必要目标 + 有效期”，人工逐条批准、可撤销、有审计。哈希或规则变化必须重新询问。目录级/解释器级/签名者级例外不由 AI 自动创建；抑制提示不等于禁用扫描。

### 3. 威胁关联必须基于采集到的事实

可以关联模型结果、规则命中、已验证签名、父子进程链、实际观察到的持久化或网络行为；对未采集项明确标“未知”。只读工具需固定白名单、有界输出、超时和取消，不能执行被检测文件、任意 Shell 或被样本提供的指令。外部信誉服务或样本上传须单独配置和授权。

### 4. 独立处置门禁

模型不是最终授权者。执行前核验事件 ID、文件身份、配置版本、用户是否已经决定以及结果是否过期。高风险确定性规则不能只因模型自述“高置信度”而放行。review、证据不足、超时或模型不可用回交用户，不静默当作安全。

### 5. 评估而非承诺准确率

建立正常软件/已知恶意/未知样本和对抗提示集，覆盖伪造签名描述、恶意文件名、规则冲突、数据缺失、文件替换、迟到结果、非法 JSON 和断连。先影子模式测量误放率、误拦率、人工复核率和延迟，尤其比较用户批准的误报抑制是否引入新的漏报。未测量前不能声称检出率提高。

## 验证方式

- tests/test_detection_evidence.py：无需模型/病毒/驱动，直接提取实际扫描方法验证分数、标签兼容、YARA 描述、缓存/线程、资源释放及 DLL 传递。
- tests/test_detection_dialog.py：验证快照、AI 上下文、精确例外身份、文件替换和原有裁决权限。
- tests/test_threat_ai_ui.cjs：真实 Chromium 页面，桥接 API 使用测试夹具；覆盖布局、主题、分数语义、动画/减弱动画、文本注入、告警与页面生命周期。
- 继续运行既有告警队列、抑制规则、AI 延迟/取消/超时、日志和菜单白名单回归。

Python 正常 Windows 环境可运行 unittest discover。Linux 的会话适配器仅把 WINFUNCTYPE 声明和窗口定位替换为测试边界，不能据此宣称验证 Windows 原生 ABI、Restart Manager、WebView2 宿主或驱动。浏览器测试可通过 EDGE_EXECUTABLE 指定已安装的 Edge/Chromium，或使用 Playwright 下载的无头 Chromium。
