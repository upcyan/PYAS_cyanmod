# 行为防御现状与细化方向

## 当前支持

驱动已有细粒度规则基础，并非只按程序名称决定是否拦截：

- 文件：创建、写入、删除、重命名等操作，结合目标路径及规则条件匹配。
- 注册表：键或值的创建、写入、删除、重命名，结合目标注册表路径匹配。
- 进程与线程：执行、映像加载、终止、挂起、句柄复制、创建线程、设置线程上下文等。
- 内存：读写进程内存、内存操作；访问权限匹配后可剥离被禁止的权限。
- 设备：部分设备控制请求，例如启动磁盘相关保护。

规则结构已有发起者、父进程、进程树、目标、命令行、操作集合、优先级等条件。是否实际拦截还取决于已启用的回调及已加载规则，不能把支持某种规则等同于覆盖所有攻击方式。

代码依据：`Plugins/Filter/DriverCommon.h`、`ProtectRules.cpp`、`ProtectFile.cpp`、`ProtectRegistry.cpp`、`ProtectProcess.cpp`、`ProtectMemory.cpp`、`ProtectBoot.cpp`。

## 当前限制

`PYAS_MESSAGE` 仅上传 `MessageCode`、`ProcessId`、`Path`。规则编号可以标识命中的规则，但同一规则可能包含多种操作，不能由编号反推出本次精确操作。

用户态目前将驱动事件记录为 `Driver protection event`。完整的请求权限、实际拒绝权限、目标 PID、注册表新值数据及执行结果没有统一上传。因此界面还不能准确说明每次事件的全部细节。

驱动已在回调中拒绝操作或剥离权限，随后发送通知；这不是等待用户选择的同步决策协议。不能仅修改弹窗就让已经拒绝的驱动操作“本次允许”。

## 推荐完善顺序

1. 增加带版本号、长度校验和事件 ID 的消息协议，保留旧版兼容。上报类别、实际操作位图、源/目标 PID、请求/拒绝权限、结果及规则编号。
2. 日志与弹窗显示“谁对哪个目标尝试了什么操作、命中什么规则、最终如何处理”。多种操作同时请求时按集合展示，不臆测具体动作。
3. 根据真实事件提供仅限动作、源身份及目标的例外。菜单集成宜限定自身组件及其注册目标，避免放行所有 PowerShell、Explorer 或整个安装目录。
4. 如需驱动事件的交互允许，再设计有界等待、用户态失联、队列上限、重入与超时策略。不能让内核回调无限等待用户，也不能把同类事件自动允许扩展到不同目标。

v3.7.0-13 先修复自身菜单组件遗漏：将安装目录内确切的 `PYAS_Menu.exe` 加入现有自动白名单，并在注册菜单前同步完成初始化。这是按程序放行，不是按行为限定的例外；驱动消息协议与细粒度交互机制尚未在本轮修改。

## ETW 溯源（已实现）

`PYAS_ETW` 现在是真实的实时会话消费者：ctypes 直调
`StartTraceW / EnableTraceEx2 / OpenTraceW / ProcessTrace`，属性解析走 TDH
（按属性名取值，manifest 的 v0/v1 字段重排由 TDH 消化）。结构体布局与
调用序列参照 pywintrace（FireEye，Apache-2.0），未引入其运行时。

订阅模型（Kernel-File，关键字掩码 0x1E90，避开 Read 的洪流）：
`10 NameCreate`/`12 Create` 建「句柄键 → 路径」关联表，`16 Write` 反查，
`26 DeletePath`/`27 RenamePath`/`28 SetLinkPath` 直接带路径。
NT 设备路径经 QueryDosDevice 映射转盘符路径后进 `PYAS_Attribution` 层 B，
弹窗溯源链：驱动事件 → ETW → Restart Manager。

- 开关 `etw_attribution_switch` 真正生效：引擎初始化与设置页热切换都会
  启停消费者；未提权时开启会被回拨（与驱动开关同款体验）。
- 弹窗「操作进程未识别」按记账层三态选词（`select_unknown_process_key`）：
  驱动开着说「文件已关闭」；仅 ETW 在跑说「未捕获写入进程」；
  两层都没有才指向「内核驱动未启用」。
- 勒索启发（`BurstHeuristic`）：单进程 10 秒窗口内改写 ≥40 个不同文档类
  文件（目标后缀集见 `BURST_TARGET_EXTENSIONS`）→ 写审计日志 + 托盘告警，
  60 秒冷却。只提醒不处置，自动处置需策略层配合。

尚未做的扩展方向（同一份数据流之上）：

- 落地关联：订阅 Kernel-Process 的进程启动事件，浏览器/邮件写入的可执行
  文件在短窗口内被启动 → 「下载即运行」告警。
- 写入时间线/进程画像：`get_etw_status()` 已暴露统计（事件计数、关联表
  占用、丢失数），UI 页面与按进程聚合视图待做。
- 自动处置：启发命中后的挂起/终止需要与告警弹窗、白名单、误报抑制打通。

仍然成立的边界：

- 事件量：已按关键字 + 监控后缀闸门（`_etw_should_track`）两级过滤，
  关联表与 pid 缓存均有 TTL 和容量上限；但管理员开启后仍有可感知的
  常驻开销，属预期成本。
- **ETW 只提供「谁在何时动了哪个文件」，不保存文件内容**。
  回滚需要内容留存，属于驱动侧（首次 `IRP_MJ_WRITE` 前做 COW 备份到隔离区）或 VSS，
  两者不可互相替代：ETW 负责知道，驱动负责留住。
- 回滚还需处理元数据一致性：ACL、ADS、硬链接与只读属性。
- 会话异常退出（如被 `logman` 等外部工具停止）会把状态沉到 `error` 并记日志，
  不自动重启；重新开关一次「进程溯源」即可恢复。

## 驱动构建（本地）

VS 的驱动平台工具集由 WDK 的 VSIX 安装、只认 VS2022；本机主 VS 是 18，工具集注册不上（MSB8020）。
因此提供直连方案，不依赖该工具集：

```bash
python build_driver.py          # 编译 + 链接，产物 Output/PYAS_Driver.sys
python build_driver.py --check  # 只编译，查语法与类型
```

脚本自动挑选最新的 MSVC 与 WDK（`Windows Kits\10\Lib\<ver>\km\x64`），
用 `cl /kernel` 编译、`link /DRIVER /SUBSYSTEM:NATIVE /ENTRY:GsDriverEntry` 链接。

注意事项：

- 内核头文件会引用 `<excpt.h>`，MSVC 的 include 必须一并加入（脚本已处理）。
- 源文件含中文注释，编译需 `/utf-8`，否则 C4819 且注释可能截断代码。
- 产出的 .sys 未签名。常规系统无法加载，需要代码签名；测试环境可开启测试签名模式。
- 仓库与安装目录目前都不含 .sys，`build.py` 也不打包它 —— 装驱动需要单独交付。
