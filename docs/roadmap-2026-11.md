## 一、本轮新发现

### 1. 冰盾 2.0→6.2.1 完整时间线(上轮只看到 5.1 起)

**值得抄(用户态可行)**:内置规则按 ATT&CK 重构+威胁评分+三级分类(基础防护/战术管理/深度狩猎,5.2/5.5);**IOA 多步行为自动拦截+打分制**(5.2);**信誉×可疑度二维自动决策**(5.1 信誉,5.2 决策);多事件关联+时间窗口约束(5.5);**规则与版本解耦热更**(5.5.3 起规则走自动升级通道,不随发版);攻击时间线/行为图/对象关联(6.0);**简单处置:禁启动+禁联网**(6.2,前者 IFEO、后者防火墙按程序规则,均免驱动);AI 攻击报告与弹窗实时研判(6.1);**MCP 服务器**(6.2,规则/事件可被 AI 操作);白加黑/侧加载检测重写(5.1)。

**确认不可行(勿模仿)**:内核同步阻断(minifilter/WFP callout)、内核增强防御(进程隐藏/APC/线程上下文)、堆栈检测(Syscall/Indirect/伪造)、**ETW-TI 订阅**(消费者需 PPL)、RegSaveKey 同步拦截(注册表内核回调)、底层磁盘读写监控。

**差异化空间**:冰盾无蜜罐文件、无 VSS 快照回滚、无云协同——PYAS 的诱饵+回滚+云三线是对的,重心应放在"规则工程+信誉决策+溯源可视化",不追内核对抗。

### 2. 开源勒索防护:技术路线存亡盘

- **死路**:内核 minifilter 拦截类项目全部停更(签名门槛+HVCI+维护成本);API hook(Detours 类)已被证明易绕过,放弃。
- **活路(与 PYAS 现路线重合)**:蜜罐/canary 被验证有效(Elastic 2024:诱饵文件可捕获勒索密钥;OpenCanary/canarytokens 持续维护)——PYAS 已有,可深化(多目录分散+熵校验);**USN Journal 用户态友好**(usnjrnl-forensic 实现了 CyberCX Rewind 式"路径重建+精准回滚")。
- **Raccine(Neo23x0 卷影删除防护)已停更**但思路可现代化:用 ETW Process 命令行层盯 `vssadmin delete shadows`/`wmic ... delete`/`bcdedit` 组合 + WMI 事件订阅,弃调试器劫持注册表的老法子(弱点:API 直调绕过、误杀备份软件)。
- 新确认:突发启发命中后**抽读采样算熵**做二次确认,可再降误报。

### 3. ETW 工程(2024-2026)

- Kernel-File/Process 是无 hook 文件遥测标准源;TI provider 需 PPL(维持上轮结论,不追)。
- 成熟做法:**单 real-time 会话合并多 provider**——Kernel-File+Process+Registry 三合一构建"进程→文件→注册表"链,注册表链可抓恢复删除类前兆(卷影删除/BCD 修改/备份服务停用,即 ATT&CK T1490)。
- **Events Lost 计数监控**:高负载丢事件时启发降级而非静默关闭;非重叠缓冲。
- **"ETW 静默即事件"自防御**:会话消失/provider 被 Autologger 注销/EtwEventWrite 被补丁(EDRSilencer 类攻击有 APT 实战)→ 静默告警+预触发 VSS 快照。PYAS 已有 ETW 溯源,这条是低成本高价值自保。
- 24H2 TI provider 新事件(image unload/handle duplication 等)需 PPL,观察即可。

### 4. YARA-X / Hyper-V / WESP

- **YARA-X 1.0(2025-06 stable)**:Rust 重写,VT 生产环境数月验证;规则兼容约 99%,重规则秒级加速;PyPI `yara-x` 包 API 仿 yara-python,**迁移成本低、收益确定**。规则集首选 **YARA Forge**(Neo23x0/Elastic/SigmaHQ 自动整合,core/extended/full 三档);老 YARA-Rules/rules 已停勿引。静态勒索检测漏检率高(加壳混淆),行为层必须并行——与现有三防线一致。
- **Windows Sandbox 爆炸流水线可行**:`.wsb` XML 纯程序化编排(映射目录+登录命令+禁网)→ 样本爆炸 → 监控落盘 → 回扫 YARA。限制:需 Pro/Enterprise + BIOS 虚拟化 + 一次性启用 Containers-DisposableClientVM;冷启动 10-20s;有反 VM 样本。**定位:可选增强,探测到可用才启用,绝不硬依赖。**
- **WESP(wesp.sys,Windows Endpoint Security Platform)**:Win11 25H2 Insider 新端点安全平台(Windows Resiliency Initiative,回应 CrowdStrike 停机),内核 ROBDD 决策图+47 类事件+用户态规则编译下发——架构正是"用户态决策+内核执行"的理想形态。**现阶段对 PYAS 不可行**:无公开文档、客户端 espclient.dll 需 AM-PPL 签名+`WESP://Permission` 令牌,面向 MVI 伙伴。列观察名单,跟踪普通 ISV 开放可能。

## 二、收敛结论(在上轮 6 条基础上新增 7-10)

1-6. 继承上轮:规则外置热更 / 豁免是数据 / audit→block 两段式 / 蜜罐标配 / USN 取证 / 信誉评分。
7. **(新)检测面从"文件"扩到"进程命令行+注册表"**:卷影删除类前兆(T1490)的拦截窗口在文件加密之前,单靠文件事件来不及。
8. **(新)自防御即检测**:ETW 静默/补丁/会话消失本身是高危信号,安全软件先保自己的传感器。
9. **(新)YARA 引擎换代是低成本确定性收益**:yara-x 迁移 + YARA Forge 订阅,规则工程从"手写"转"策展"。
10. **(新)响应动作升维**:从"弹窗裁决"扩到"禁联网/禁启动/自动回滚"的组合拳,弹窗只是其中一档。
