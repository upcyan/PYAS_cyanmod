## 一、调研对象与核心发现

### 商业对标:冰盾主动防御系统(iDefender,HIPS+EDR+AI)

从其前端资源包提取了完整 changelog(5.1→6.2 全版本)与 UI 帮助文档:

- **规则自动下发**:5.2 起"规则更新通过自动升级下发,不更新版本"——误报治理与规则迭代和发版解耦;
- **内置规则三档模式**:基础防护(开箱即用零弹窗)/战术管理(ATT&CK)/深度狩猎(专家),按用户水平切换;
- **学习模式**:干净系统首装开启,所有弹窗默认信任并记录进信任列表,关闭后相同事件自动放行;
- **信誉体系**(5.2):自动允许高信誉进程的低可疑行为、自动拦截低信誉进程的高可疑行为;
- **攻击链可视化**(6.0):攻击时间线/行为图/对象关联(服务创建、计划任务、快捷方式、压缩包解压溯源);AI 实时分析事件生成攻击报告;
- **响应动作档位**:询问(默认拦截/默认允许/默认结束进程)三档超时语义。

### 开源杀毒引擎(ClamAV/Loki/PMF/Defender ASR 等)

- **Loki**:IOC/规则带 `score` 与误报正则字段,GREEN/YELLOW/RED 三级评分,`--allreasons` 输出扣分理由(告警可解释);
- **Defender ASR**:新规则 **audit→block 两段式上线**;防勒索策略="拦截尚无良好信誉的文件"而非仅拦已知恶意;
- **PHP Malware Finder**:内容级 `whitelist.yar`(hash 模块白名单,不依赖路径);
- **用户态能力边界**(权威结论):同步阻断写入、ETW-TI 通道必须内核/PPL,Python 进程拿不到;**用户态可达上限 = USN Journal + ETW 文件事件 + 高熵/改名风暴/蜜罐/卷影删除检测 → 检测+弹窗+事后回滚**;PYAS 用户态 ETW 路线正确,快速回滚就是我们的"阻断"。

## 二、收敛结论(三方独立指向)

1. **规则/参数与程序分离、可热更**(三方全部采用)——PYAS 每轮误报修复都发版,是结构性落后;
2. **误报豁免是数据不是代码**(双键精确豁免+分文件+可下发);
3. **新检测 audit→block 两段式**(先只记日志观察误报率);
4. **蜜罐文档是行业标准**(多方标配),且存在内容指纹对抗面(已修:随机正文+ADS 声明);
5. **USN Journal 作为 ETW 的补充/重启后取证通道**;
6. **进程信誉评分**(签名+知名度+行为累积)替代二元判定,是签名×安装树绑定的自然演进。

## 四、执行注意事项

- 规则/参数外置必须带**引擎-规则版本兼容矩阵**与**加载失败回退旧包**(ClamAV 教训);
- 新增检测上线走 audit 两段式,避免勒索启发这类误报反复;
- 蜜罐对抗教训:内容指纹(含 PYAS/诱饵/防护字样)会被嗅探跳过——正文随机化+声明走 ADS;未来再加诱饵类型同样遵守;
- 用户态边界不要试图突破:同步阻断与 ETW-TI 需要内核/PPL,围绕"检测+弹窗+快速回滚"设计。
