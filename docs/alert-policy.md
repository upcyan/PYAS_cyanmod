# 交互告警与防洪策略

默认不超时执行；仅用户开启“超时自动拦截”后，当前显示的告警开始倒计时。排队中的告警不计时。应用退出或界面无法创建时，未决请求按拦截释放。

## 队列

- 一个持久弹窗，按进程、文件、网络防护聚合显示数量；同类不同路径不逐行挤满界面。
- 请求仍按到达顺序处理，各类内部保持先来先处理。分类数量不代表一次决定放行整类。
- 仅同一防护、完整路径、SHA-256、检测结果、目标及 PID 完全相同的在途请求合并，界面显示重复数量。用户的决定仅作用于当前请求及其完全相同的重复请求。
- 最多容纳 256 个请求（含合并的重复请求）。达到上限时通过现有防护工作池施加背压，等待容量；不额外创建弹窗或线程，不丢弃告警、不自动允许，也不因容量限制新增超时决策。等待期间进程可能维持暂停，文件可能维持锁定。

## 永久允许

按钮位于窗口底部最左侧，与“本次允许”留有间隔。点击后显示具体路径与 SHA-256，并再次确认。

永久规则单独保存在 `alert_allow_rules`，不加入普通白名单，也不跳过扫描。命中后仍需满足防护类型、规范化完整路径、SHA-256 文件内容、检测结果、扩展/敏感扫描设置和目标全部一致。网络目标包括 IP 与端口。相邻目录、同名文件、相似路径、其他目标均不继承允许。

文件变更、检测结果变化、敏感/扩展扫描设置变化后重新询问。保存时重新计算身份，保存失败则撤销新增规则。允许结果返回防护调用方前再次验证文件身份。文件锁由本进程持有时，从已持有句柄读取并恢复位置，保持锁定，不先解锁再计算哈希。

无法读取、超过 64 MiB 或身份无法稳定验证的文件，以及仅凭磁盘内容无法确定身份的内存 DLL 告警，禁用记住决定功能，仍可单次选择。永久规则最多 256 条；满额后拒绝新增规则，不自动删除旧规则。

## 短时重复操作

每次决定单独勾选，默认关闭。仅精确相同的告警重复允许或拦截，固定 30 秒且最多 20 次；重复命中不延长有效期。仅保存内存，退出即失效。

已有排队项也按精确身份匹配短时决定，文件变化后不会沿用允许。只根据“同类问题”或“同类路径”推断允许没有足够证据，本实现不使用这种扩大范围的策略。

设置中的“清除已记住的告警决定”可撤销全部永久和短时规则，保留普通白名单。规则新增和自动复用均写入日志。

## 新版右键菜单与更新

安装包同时包含 COM 菜单程序、稀疏 MSIX 包及注册脚本。安装末尾以原交互用户注册；配置关闭右键扫描时保持关闭。设置开关同时管理传统与新版菜单。卸载撤销当前用户注册。源代码启动只注册传统菜单，正式安装版才注册新版菜单。

本地菜单包使用自签证书。安装器在管理员阶段校验公钥证书的 SHA-256 指纹、身份、有效期与唯一代码签名用途后，将其导入本机 TrustedPeople；随后为当前用户注册菜单。私钥不进入安装包，公开发行时应更换为正式代码签名证书。Explorer 缓存可能需要重新打开资源管理器或重新登录才能刷新；不会自动终止 Explorer。

更新检查区分仓库不可访问、限流、网络失败和异常响应，跳过草稿与预发布，并按版本号选择最新版本。仅选择当前项目的 PYAS_Setup 安装包，下载校验大小及 GitHub 提供的 SHA-256（若提供），不自动降级或自动安装。
